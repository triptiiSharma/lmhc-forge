# PHASE5_SAMPLE_DESIGN.md

**Status: design + sample generated. Labeling NOT started.** This document
describes the stratified sample for Phase 5 (independent manual ground-truth
review) and the blinded protocol for using it. No manual review has been
performed — `results/validation_sample.csv`'s reviewer columns are empty.

## Why this exists (task §15's non-circularity requirement)

`checker_verdict` (from `classify_binary.py`) cannot be evaluated for
accuracy against itself, and `source_intent_label` (which Z construct was
*requested*) is not automatically the binary truth — the whole point of
this study is that compilation can silently change or remove the
requested structure. `binary_ground_truth` must come from an independent
process: two humans reading raw SASS, blind to what the checker said,
reconciling disagreements. Phase 5 is that process; this document is its
design.

## Sample composition

Generated by `scripts/select_review_sample.py` (deterministic, seed
`20260801`, fully reproducible — rerun it and you get the same 254 rows).
**254 artifacts selected** from the 2,018-record corpus (2,016 core matrix
+ 2 pilot flag-recheck cells), close to the ~250 target.

| Tier | Rule | Count | Rationale |
|---|---|---:|---|
| 1 | every `COMPILE_FAILED`/`COMPILE_UNSUPPORTED`/`UNDECIDABLE` record | 0 | none exist in this corpus (Phase 4 finding) — rule is unconditional, stays correct if that ever changes |
| 1 | both pilot flag-recheck cells | 2 | categorically distinct (only records with `extra_device_flags` set) |
| 2 | base stratified layer: 5 per (construct, context) combination, rotating deterministically through (ptxas opt, arch, toolkit) so the 210 draws spread across all values of every other dimension | 210 | this is the layer that gives the ~250 sample its breadth — every one of the 42 construct×context cells the paper's claims are structured around gets independently reviewed, not just aggregated |
| 3a | O0 indirect zero-store cases (`zero_shared_store_indirect_count > 0`), capped at 15, stratified across construct×context | 15 | this is the exact code path that produced one real bug in Phase 3 (PLAN.md §9 / VALIDATION_REPORT.md) — the newest, least-trusted part of the parser gets extra scrutiny, not just its base ~17% share of a size-254 sample (which would be ~43) |
| 3b | multi-EXIT cases (`exit_count >= 3`), capped at 15, stratified across construct×context | 15 | Phase 4 found **zero** real `exit_count>=3` cases ever reach `FULL_SIGNATURE` — this oversample specifically lets reviewers check whether that's a genuine finding or an artifact of the classifier's conservative fallback masking something |
| 3c | extra draws from `sm_75` and `sm_90` (the two architectures with no hand-traced manual verification anywhere in Phase 3/4), 6 each, spread across distinct constructs | 12 | targets the explicit residual gap flagged in VALIDATION_REPORT.md: "sm_75/80/87/90... no dedicated manual trace... has been done for those four targets yet" |

**Coverage confirmed programmatically** (not just claimed): all 7
constructs, all 6 contexts, all 4 opt levels, all 6 archs, both toolkits,
and all 4 verdict categories that actually occur in the corpus
(`FULL_SIGNATURE`, `PARTIAL_SIGNATURE`, `STORE_ONLY`, `ABSENT` —
`UNDECIDABLE` has zero real instances to sample, correctly not fabricated)
are present with **zero missing values** in the selected 254.

Earlier iterations of this script initially over-selected (825 rows) by
naively including *every* record matching the tier-3 "unusual pattern"
criteria — those patterns turned out to be ~15–17% of the whole corpus,
not rare edge cases, so "oversample" was redefined to mean *proportionally
more than a plain random sample would give them*, via a fixed cap plus
stratified subsampling within the cap, not literal inclusion of every
matching record.

## Files produced

- **`results/validation_sample.csv`** — the blinded working file for
  reviewers. Columns: `artifact_id, selection_reason, zeroization_construct,
  kernel_context, target_arch, ptxas_optimization, cuda_version, sass_path,
  source_file, reviewer_1_label, reviewer_1_notes, reviewer_2_label,
  reviewer_2_notes, disagreement, resolved_binary_ground_truth`. The last
  five columns are empty, to be filled in during Phase 5. **Deliberately
  excludes `checker_verdict` and `checker_detail`** — a reviewer working
  from this file cannot see what the automated checker concluded.
- **`results/validation_sample_answer_key.csv`** — same 254 artifact IDs,
  WITH `checker_verdict`/`checker_detail`/`source_intent_label`. **Not for
  reviewer use.** Exists only for the Phase 6 comparison step, and should
  be kept separate from whatever reviewers are given access to while
  labeling is in progress.

## Blinded review protocol (for Phase 5, when approved)

1. Each reviewer works **only** from `validation_sample.csv`'s
   `sass_path`/`source_file` columns plus a shared, pre-written codebook
   (below) — never from `classify_binary.py`'s output, never from
   `validation_sample_answer_key.csv`, and never by running the checker
   script themselves on these artifacts until after their own label is
   recorded.
2. For each artifact, the reviewer reads the raw SASS at `sass_path` and
   independently records one of the five ground-truth categories (the
   same taxonomy the checker uses — `FULL_SIGNATURE`, `STORE_ONLY`,
   `PARTIAL_SIGNATURE`, `ABSENT`, `UNDECIDABLE` — this is a shared,
   pre-defined codebook, not something invented per-artifact) into their
   own `reviewer_N_label`/`reviewer_N_notes` columns, in a **private copy**
   of `validation_sample.csv` (so reviewer 1 cannot see reviewer 2's
   answers while working, and vice versa).
3. **Codebook** (identical wording to `PLAN.md §5`'s classifier rules,
   given to both reviewers verbatim so disagreements reflect genuine
   judgment calls, not differing definitions):
   - `ABSENT`: no zero-valued store to the named kernel's sensitive shared
     buffer is present anywhere in the SASS.
   - `STORE_ONLY`: a zero-valued store is present, but neither a
     `MEMBAR.SC.CTA` nor a `BAR.SYNC` appears after it.
   - `PARTIAL_SIGNATURE`: a zero-valued store plus at least one of
     `MEMBAR.SC.CTA`/`BAR.SYNC` is present, but not both in the correct
     order, or the order is violated.
   - `FULL_SIGNATURE`: zero-valued store, then `MEMBAR.SC.CTA`, then
     `BAR.SYNC`, all before every exit the reviewer judges reachable after
     the store.
   - `UNDECIDABLE`: the reviewer cannot confidently assign one of the
     above from static reading alone (e.g., genuinely ambiguous multi-exit
     control flow, an unfamiliar instruction encoding).
4. Once **both** reviewers have completed all 254 independently, the two
   private files are merged into the shared `validation_sample.csv`'s
   `reviewer_1_label`/`reviewer_2_label` columns.
5. Any row where `reviewer_1_label != reviewer_2_label` is marked
   `disagreement = TRUE` and resolved by joint discussion (both reviewers
   re-examine the SASS together) — the resolution goes in
   `resolved_binary_ground_truth`. Rows with agreement get
   `resolved_binary_ground_truth = reviewer_1_label` directly.
6. Only **after** `resolved_binary_ground_truth` is finalized for all 254
   rows does anyone consult `validation_sample_answer_key.csv` — that
   comparison is Phase 6 (checker evaluation: false accepts, false
   rejects, undecidable rate), not Phase 5.

## What Phase 5 will NOT do (kept explicit so it isn't quietly expanded)

Does not touch the sensitivity study, negative-case corpus construction,
portability probes, or any manuscript text. Produces exactly one artifact:
a fully independently-labeled `resolved_binary_ground_truth` column for
these 254 rows, ready for Phase 6 to consume.
